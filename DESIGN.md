# Lagar app: design

How the on-device Lagar is built and the rules behind it. It is the successor of the Python version in the
[`lagar`](https://github.com/ronsel-eu/lagar) repository, whose `DESIGN.md` explains where many of these rules come
from. This file describes the current design of this app.

## Principles

- **Simple for the owner, shareable with others.** One person's cellar first; nothing in the app assumes who that is.
- **Your cellar stays on your device.** No server, no account, no tracking. The price of that is a backup file the
  person has to make, so Settings says it plainly.
- **Show data, do not justify it.** No "assumed", "estimated" or "not set" wording next to a value. An empty value is a
  dash. The one place that says where a value comes from is the drinking advice (its source and the table used).
- **Short and to the point.** Guides are one table or a few lines. Pages avoid long explanations.
- **Dates as dd/mm/yyyy**, stored as ISO (yyyy-mm-dd).
- **Nothing is guessed, nothing is deleted by an import.** The vintage is a year, or `NV` typed by the person. An
  import only adds wines or adds bottles to what is already there.
- **Never fail silently.** If something cannot be saved, a red message says why, on the same page.

## Look

From the Paper file "Lagar: two directions": chalk ground (`#F3F2ED`), Archivo, ink rules, no ornament. Dark mode is
not supported.

- **Bands.** Every wine type has a band colour (`--band-*` in `src/app.css`, same names as the Paper tokens): red
  black, white mustard, rosé blue, fortified brown, sparkling green, sweet orange, cider apple green.
- **Label band (the logo).** The same on every page; its colour is one of five (red, white, rosé, fortified,
  sparkling). It keeps its colour while the app is in use and changes after 30 minutes without use (`src/lib/band.ts`).
  The letters carry a small spacing: L and R +0.015em, A, G, A -0.015em. The same ratio is used in the app icon.
- **One wine row everywhere** (`WineList.svelte`): type band, name in bold and bottles; second line appellation,
  winery, vintage, price. The wine page name band splits the name into prefix / main word / suffix (`nameParts` in
  `src/lib/wine.ts`).
- **Row tags and counts** (Now / Soon / Young, ×2): one fixed 60px column at the right of every wine row, text
  left-aligned, so tags and counts share one left edge. 60px fits the longest words in the three languages (PRONTO,
  BIENTÔT); a longer word would need a wider column.
- **Home numbers row** (bottles, wines, drink now): numbers and labels centred in each column, labels below the number
  in soft grey (Drink now: reddish grey, bold, with the number in wine). Numbers are 52px; if any of the three reaches
  1.000 all three drop to 34px, so the row never changes height. Thousands use a period (1.248), as in the cellar cost.
- **Welcome page** (empty cellar): one message, the same on Home and on Wines (`Welcome.svelte`). Design reference:
  Paper, "Home · empty cellar · welcome only".
- **App icon.** The label and its colour spine: an ink band with LAGAR over four stripes (white, rosé, fortified,
  sparkling) on chalk. The maskable version has extra margin for Android's round and squircle masks.
- **Safe areas.** The layout respects the notch and the home bar on phones (`viewport-fit=cover`).

### Messages

One band for every message, placed at the top of the page (`Notice.svelte`). It is never an outlined box, which would
look like an input.

- **Done** (ink background): a tick that draws itself, the text, a cross. It slides in (240 ms), a thin line along the
  bottom shrinks over 7 seconds, then it slides away. Tap the band or the cross to close it earlier.
- **Needs attention** (wine-red background): a "!" mark, the text, a cross. No timer: it stays until closed.
- With reduced motion on, nothing moves.
- A message belongs to one page (`say(text, warn, path)` in `src/lib/flash.svelte.ts`) and goes away when the person
  leaves that page.
- Opening a bottle says how many are left: "last bottle", "one bottle left", or "still N to share with friends";
  trying to open more than you have asks you to wait for a better occasion.
- Design reference: Paper, page "K Messages" (approved).

## Stack

Svelte 5 (runes), TypeScript, Vite, vitest. No UI library. Everything runs in the browser.

| Part | How |
|---|---|
| Screens | `src/components/*.svelte` |
| Logic without screens | `src/lib/`: advice engine, import, browse and filters, storage, backup, i18n, guides |
| Storage | IndexedDB behind a small `LagarStorage` interface (`src/lib/storage.ts`); an in-memory version for tests and as a fallback when the browser database is not available |
| Router | A tiny router on the URL hash (`#/wines?country=Spain`), so the app works from any sub-path with no server rules |
| Font | Archivo, served from the app (`@fontsource/archivo`, generated by `tools/make_fonts.mjs`): no external requests |
| Offline | `tools/sw-plugin.ts` writes `sw.js` at build time (see below) |
| Deploy | Push to `main`: GitHub Actions runs the tests, builds, publishes to GitHub Pages |

### Data model (`src/lib/types.ts`)

- **Wine**: one record per wine and vintage: name, vintage (a year or `NV`), bottles in the cellar now, type, producer,
  country, region, appellation, grapes, price paid per bottle, critic points (50 to 100), last purchase date, the
  person's own drinking window, and the fixed "More detail" rows.
- **Opened bottle**: wine, date, quantity, occasion, note.
- Everything stored is plain JSON. The screens hold their data in reactive objects, which the browser database cannot
  clone, so storage always writes a plain copy.

### Backup

Settings → Export backup saves one JSON file with everything (`{ app: 'lagar', version, wines, opened, settings }`).
Restore replaces the cellar in one transaction: if anything fails, nothing changes. A backup from a newer version is
refused with a message. This is also how a cellar moves between devices.

## Drinking advice

The engine (`src/lib/advice/engine.ts`) is a port of the Python rules, checked against golden files generated from the
original (`tools/make_golden.py`). Statuses: *drink now*, *drink soon*, *can wait*, *keep*, *evolves*.

Two rules now differ on purpose from the Python original, which keeps its own rules for testing: Barolo without a style is
6 to 20 years (the original has 6 to 15), and Chianti Colli Senesi is 2 to 5 years (the original treats it as basic Chianti).
The two Barolo cases in `golden.json` were edited by hand to match, so regenerating the golden file from the original will
bring those two cases back to its values and the tests will flag them.

Priority:

1. **The person's own window**, set when editing the wine. It always wins.
2. **Style rules**: regional tables by appellation, then general rules by wine type.

Vintages of the last 4 years are never *drink now*: they are shown as *drink soon*. Critic and shop drinking advice is
**not stored**: if someone follows a critic, they set that as their own window. Critic **points** are kept, to sort
and to show; they never change the advice.

The wine page ("Drink" block) shows the status and the end of the window, then one short sentence and its source ("your
own decision", "general style rules", or "the Consejo Regulador" for sherry), with a link to the table. A wine with no
window says "No window known, so no rush."

### Wine page "More detail"

Appellation, Grapes, Serving temperature, Food pairing, Appearance, Nose and Palate, in that order, with a dash when
empty. Edit this wine, delete and open a bottle are on the same page.

### Wines filters

- Filters combine with AND. **Each filter only offers what still fits the others, with counts.** If a choice no longer
  fits after another filter changes, it is dropped.
- **The drinking status is a filter like the others.** It shows how many wines each status gives with the current
  choices, and a status that would give nothing is greyed out, so choosing it can never clear the other filters.
- Years are newest first with NV last. Country and type are ordered by how many wines they give, the rest
  alphabetically, ignoring accents. Grapes are matched one by one (`Tempranillo; Garnacha` counts under both), and
  different spellings of the same variety are merged.
- The filters live in the page address, so the browser's Back button restores them. The "Wines" link on a wine page
  also returns to the filters you had; the "Wines" tab and "Clear filters" start clean.

### Home

6 suggestions: for each of red and white, one *now*, one *soon* and one *young* wine (the last 4 vintages, not already
*now*), filled from the other wines if one is missing. 3 wines to drink now: 2 red and 1 white. All random, and new each
time Home is opened. Rows in the drink-now list show the number of bottles instead of a tag.

## Rules for the numbers

- **Stock** is the bottles in the cellar now. Opening a bottle subtracts; Undo puts it back.
- **Cost** = bottles in the cellar × price paid per bottle. Wines in the cellar with no known price are counted
  separately and not valued at 0.
- **Types** are colours only: red, white, rosé, sparkling, fortified, sweet, cider.
- Above 9.999 bottles or wines is out of scope: that is a different kind of app.

## Import

`#/settings/import`: three steps on one page: download the template, copy the AI-assistant prompt (in English, Spanish or
French; the column names and type words always stay English), upload the file.

- Preview first (`previewImport`): every row is New, Restock (a wine already there gets the bottles added), Same or
  Skipped. Nothing is saved until the person confirms.
- Template columns: `name, vintage, bottles, type, producer, country, region, appellation, grapes, paid,
  purchase_date`. Optional columns outside the template: `drink_from`, `drink_to` (the person's own window) and `points`
  (critic points).
- Accepts `,` `;` or tab as separator, UTF-8 or Windows-1252, Spanish / French / English column names and types.
- The file picker accepts any file (Android greys out a CSV that the phone's apps label as a spreadsheet), and the CSV
  text can also be pasted.
- The confirm button locks while it works, shows "Importing…", and a failure is shown as a red message.
- *Try a sample cellar* loads 30 made-up wines with every type, enough to fill every section of Home. It only shows
  while the cellar is empty.
- The importer is a port of the original, checked against golden files (`tools/make_import_golden.py`).

## Languages

- English, Spanish and French, chosen in Settings and remembered on the device. The browser's language is the default.
- The English text is the key: `t('English text')`. The translations come from the original's `app/i18n.py`, copied by
  `tools/make_i18n.py` into `src/lib/i18n/strings.ts` (generated, do not edit); texts added since are in
  `src/lib/i18n/extra.ts`. Text without a translation is shown in English.
- French keeps its usual spacing before `:` and `?`.
- Country and region names are translated for display; the stored value does not change.
- Not translated, by decision: wine descriptions and the sentences of the drinking advice.
- Guides: one markdown file per language (`slug.md`, `slug.es.md`, `slug.fr.md`), with the same English anchors in the
  headings (`## Xérès {#sherry}`), because the wine page and the other guides link to them.
- To add a language: add it to `LANGS`, a column to the strings, and a guide file for each guide.

## Offline and updates (PWA)

- `public/manifest.webmanifest`, icons in `public/icons/`, iOS tags in `index.html`. Android shows an Install button in
  Settings; iPhone and iPad show a one-time hint on Home (and the same steps in Settings), and neither shows inside the
  installed app.
- `sw.js` is written at build time with the list of every built file and a version that changes with their content. It
  answers from its cache first, falls back to `index.html` for page loads, and deletes older versions' caches.
- Every file is downloaded **past the browser's own cache** when a new version installs, and the worker script is
  registered with `updateViaCache: 'none'`. GitHub Pages lets browsers keep `index.html` for ten minutes, and an old
  `index.html` pointing at files that no longer exist would leave a blank page.
- A new version takes over on the second open: the first downloads it, the second runs it.
- If the app cannot start, the page says why instead of staying blank.
- Settings shows the time of the build (UTC), to tell which version a device runs.

## Adding to the app

- **A new guide:** a markdown file in `src/guides/` with a small header (`title`, `summary`, `order`) and a translation
  next to it for each language.
- **A new regional table for the drinking advice:** a rule in `src/lib/advice/engine.ts`, a section in the
  consumption-windows guide, and a golden case.
- **A new field on the wine:** `types.ts`, the form (`WineForm.svelte`, `wine.ts`), the backup reader (`backup.ts`, with a
  default for old backups), the importer if it is a column, and a row on the wine page.

## Limits

- The cellar lives in one browser on one device. There is no sync: the backup file is the way to move it.
- Clearing the site data in the browser deletes the cellar. Private windows do not keep it.
- The importer reads one wine per line and does not merge duplicate lines of the same wine and vintage in a file: the
  second one is skipped.
- Wine descriptions and the sentences of the drinking advice are in English.
- Android and iOS store versions (Capacitor) are not built yet.
